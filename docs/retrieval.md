# Retrieval and citations

When a user asks a question, DIVA gathers relevant records and source spans,
then asks the model to write an answer from that material. The browser receives
the answer as a stream and can open each citation on the source page.

## Request flow

```mermaid
flowchart LR
    Q[Question] --> PLAN[Classify the question]
    PLAN --> TOOLS[Search or field tools]
    TOOLS --> BUNDLE[Evidence bundle]
    BUNDLE --> WRITE[Write the answer]
    WRITE --> GUARD[Check citation ids]
    GUARD --> UI[Stream answer + citations]
    UI --> PDF[Open page highlight]
```

The planner chooses the shape of the work. It does not answer the question.
The retrieval loop can call more than one tool, combines the returned evidence,
and sends that bundle to the answer-writing step. Citation ids that were not in
the bundle are removed before the answer reaches the browser.

## Available tools

| Tool | Use |
| --- | --- |
| `vector_search_evidence` | Find semantically similar evidence spans |
| `vector_search_sections` | Find relevant document sections |
| `vector_search_blocks` | Find relevant page blocks |
| `keyword_search` | Find exact words or phrases |
| `lookup_verified_fields` | Read fields from the structured knowledge layer |
| `aggregate_ops_fields` | Filter and calculate totals over structured fields |
| `lookup_defined_term` | Find a defined term and its source |
| `lookup_section` | Retrieve a named section |

Tools return evidence records rather than only text. An evidence record may
include the document, page, snippet, field, confidence tier, and rectangles.
The server filters results for the caller's role before they are given to the
retrieval loop.

## Which path answers which question?

| Question shape | Preferred path |
| --- | --- |
| Find a clause with similar meaning | Vector search, usually followed by a citation |
| Find an exact phrase or defined term | Keyword or defined-term lookup |
| Read the current value of a known field | Verified-field lookup and the document-family walk |
| Compare or total values | Structured field lookup and `aggregate_ops_fields` |
| See how a section is worded | Section lookup with its page evidence |

Arithmetic and filters run in Python or the store query layer. The model can
choose the aggregation tool and explain its result, but it is not responsible
for adding the numbers.

## Citations in the answer

The answer writer receives ids such as `[ev:evidence-id]` beside the evidence
it may use. The citation layer then:

1. removes ids that were not returned by a tool in this request,
2. upgrades a raw span to a verified field citation when the same value is
   available, and
3. forwards the answer text and allowed ids to the browser.

The browser requests `/evidence/{evidence_id}` when a citation is selected. The
response contains the page number, the source snippet, and the rectangles used
to draw the highlight. Citation geometry is not generated by the answer model.

## Access control

The API derives the caller's role from the session. The client cannot send its
own clearance, and the retrieval code applies the policy before returning
records. This applies to both text search and structured field tools.

| Role | Access |
| --- | --- |
| `admin` | All application areas and administration |
| `confidential` | Chat, knowledge, and explore, including confidential values |
| `default` | Chat with restricted values withheld |

An approved-verifier flag controls access to the Review area separately from
the role. See [Reference](reference.md) for the endpoint map and
[Deployment](DEPLOYMENT.md) for shared-instance settings.

## When an answer needs investigation

Start with the evidence shown beside the answer. If the source text is right
but the value is wrong, review or correct the field and rebuild the knowledge
projection if required. If the page is right but the rectangle is wrong, use
the evidence re-anchoring command in [Reference](reference.md).

For a new question, create a new chat thread after changing evidence. Existing
threads store the citation data used when they were created.
